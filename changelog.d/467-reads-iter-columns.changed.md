- **`Reader::reads()` is ~5x faster per read (826 -> 156 ns/read on a 700k-read POD5; `escpod view` ~45% less wall, ~64% less CPU).** The iterator did ~22 `column_by_name` schema scans and one `end_reason` string parse per row. It now resolves the batch's columns once, when the batch is loaded, through `ReadsBatchView` (which now holds `Arc`-backed column handles instead of borrows, so it can live beside the batch in the iterator; its public API is unchanged), and `ReadsBatchView` parses each `end_reason` dictionary entry once instead of per row. The `ReadData` produced is identical, field for field. A batch whose columns cannot be resolved still falls back to the per-row extractor, so malformed-file errors are unchanged. `collect_all_reads()` measures ~2% slower (194 -> 198 ns/read) from the owned handles.
